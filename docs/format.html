Dockanfile, la rekomendita formato

Dockanfile aspektas kiel Dockerfile, sed ĉio restas sur via maŝino.

FROM scratch
LABEL org.opencontainers.image.title=MyApp
WORKDIR /app
COPY . /app
RUN chmod +x ./start.sh
CMD ./start.sh

Konstrui kaj ruli:

dockan build -t myapp:latest .
dockan run myapp:latest

Dockan unue legas Dockanfile. Se ĝi ne ekzistas, ĝi legas simplan lokan Dockerfile.

Subtenataj instrukcioj

  • FROM, COPY, ADD, RUN, CMD, ENTRYPOINT, ENV, WORKDIR
  • EXPOSE, VOLUME, LABEL, ARG, USER, SHELL, STOPSIGNAL, HEALTHCHECK

Dockan ankaŭ komprenas:

  • la dosieron .dockerignore
  • simplajn plurŝtupajn konstruojn per FROM ... AS ... kaj COPY --from=...
  • komandojn en Docker-formo, ekzemple CMD ["node", "server.js"]
  • lokajn bazojn importitajn per dockan base import

Uzu LABEL anstataŭ la malnova instrukcio META, kiu ekzistis nur en Dockan.

Lokaj bazoj

Importu bazon el dosierujo aŭ el arkivo:

dockan base import alpine:local ./alpine-rootfs
dockan base import ubuntu:local ./ubuntu-rootfs.tar.gz

Poste uzu ĝin:

FROM alpine:local
COPY app.sh /app.sh
CMD ./app.sh

Vi povas ankaŭ elŝuti normajn bildojn rekte el Docker Hub, GHCR aŭ Quay, ekzemple dockan pull alpine:latest, aŭ fiksi ilin per ilia haketaĵo: dockan pull alpine@sha256:....

La malnova formato .dockan

La malnova dosieruja formato ankoraŭ funkcias por tre simplaj aplikaĵoj:

myapp.dockan/
  meta.conf
  build.sh
  start.sh
  rootfs/
  hooks/
  volumes/
  logs/
  • meta.conf: la metadatumoj
  • build.sh: nedeviga konstruskripto
  • start.sh: la enirpunkto
  • rootfs/: la dosieroj de la aplikaĵo
  • hooks/: skriptoj rulataj antaŭ aŭ post iuj agoj
  • volumes/: lokaj daŭraj datumoj
  • logs/: la protokoloj de rulado

Por novaj projektoj, preferu Dockanfile.
