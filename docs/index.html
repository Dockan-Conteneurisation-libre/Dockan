Ujoj por Linukso, sen demono.

Dockan elŝutas bildojn el Docker Hub, GHCR, Quay aŭ via propra dosierujo, kontrolas ilin kaj lanĉas ilin kiel ordinarajn procezojn, kiujn vi vidas kaj regas. Neniu fona servo, neniu konto, neniu nubo.

Instaliĝas en ~/.local/bin sen sudo. Libera programaro sub AGPL-3.0.

Nenio inter vi kaj via aplikaĵo

Docker funkcias per konstanta demono, kiu defaŭlte ruliĝas kiel root kaj posedas ĉiujn ujojn. Dockan lanĉas vian aplikaĵon rekte el via ŝelo aŭ el systemd, en izolejo de bubblewrap. Jen la procezarboj, tiaj kiaj ilin montras ps.

De nulo al servo en kvar paŝoj

La samaj komandoj por provo sur via tekkomputilo kaj por servo, kiu daŭre funkcias sur servilo.

  1. Instali

    Unu skripto instalas la ĝustan pakaĵon; dockan doctor montras, kiun izoladon via sistemo ofertas.

    dockan doctor

  2. Akiri bildon

    Elŝutu ĝin el registro aŭ konstruu ĝin el Dockanfile aŭ Dockerfile.

    dockan pull nginx:alpine
dockan build -t app .

  3. Ruli

    En malfono por provi, aŭ en fono kun protokoloj kaj komandoj ene de la ujo.

    dockan run -d --name app app
dockan logs app

  4. Konservi ĝin aktiva

    La aplikaĵo iĝas ordinara servo de systemd, kiu startas kun la maŝino.

    dockan compose autostart

Ĉio por memgastigi aplikaĵojn

Unu binaraĵo en Go, sen eksteraj dependaĵoj. Legeblaj dosieroj, arkivoj kaj kontrolsumoj.

Bildoj el Docker Hub, GHCR kaj Quay
Ĉiu tavolo estas kontrolata per sia haketaĵo antaŭ ol esti malpakita, rekte en pura Go.
Dockanfile kaj Dockerfile
Oftaj instrukcioj, .dockerignore, lokaj bazoj kaj simplaj plurŝtupaj konstruoj per COPY --from.
Compose
dockan compose up legas dockan.yml aŭ docker-compose.yml: build, image, ports, env, volumes, aliases, depends_on, restart, healthcheck, memory kaj cpus.
Servoj de systemd
dockan compose autostart instalas vian aplikaĵon kiel ordinaran servon, kiu startas kun la maŝino.
Daŭraj datumoj
Nomitaj volumoj, muntado de lokaj dosierujoj kaj sekurkopioj tar.gz, kiujn vi povas restarigi.
Loka registro
Dosierujo sufiĉas kiel registro: dockan push kaj dockan pull kun arkivoj kaj kontrolsumoj, ankaŭ sur NAS sen interreto.
Ruli, legi protokolojn, eniri
Lanĉo en malfono aŭ fono, inspektado, haltigo, forigo kaj komandoj ene de ruliĝanta ujo.
Sankontroloj
dockan health kaj dockan compose health kontrolas, ĉu viaj servoj pretas respondi.
Ĉiu Linuksa rultempo
PHP, Node.js, Python, Go, Rust, Java, Ruby, ŝelaj skriptoj kaj statikaj binaraĵoj.
Reto
Simplaj retoj kun kaŝnomoj, aŭ ponto kaj NAT kun publikigitaj pordoj (bezonas sudo).

Kion Dockan kontrolas por vi

Elŝutita bildo estas kodo, kiun vi ne verkis. Dockan traktas ĝin tiel.

  • Kontrolitaj haketaĵoj

    La manifesto, la agordo kaj ĉiu tavolo devas kongrui kun sia haketaĵo sha256 aŭ sha512 kaj kun sia deklarita grandeco. Alie la elŝuto ĉesas.

  • Malpakado ene de la bildo

    Simbolaj ligiloj kaj forviŝaj eroj de tavolo neniam povas skribi aŭ forigi dosierojn ekster la radiko de la bildo.

  • Neniu kaŝita malizolado

    Se neniu izolilo disponeblas, Dockan rifuzas lanĉi la bildon. Ruli sen izolado ĉiam postulas eksplicitan --isolation=none.

  • Apartaj nomspacoj

    Kun bubblewrap, ĉiu ujo havas proprajn nomspacojn PID, IPC kaj UTS, sen ajna Linuksa kapablo. Fonaj ujoj ne havas aliron al via terminalo.

Detaloj kaj limoj troviĝas en la gvidilo por produktado.

Instali

Dockan instaliĝas el la eldonoj sur GitHub. La instalilo elektas la pakaĵon por via arkitekturo kaj kontrolas ĝiajn kontrolsumojn.

Por via uzanto, sen sudo

curl -fsSL https://raw.githubusercontent.com/Dockan-Conteneurisation-libre/Dockan/main/scripts/install.sh | sh

Se Dockan instaliĝas en ~/.local/bin, aldonu tiun dosierujon al via PATH kaj kontrolu la instalon:

export PATH="$HOME/.local/bin:$PATH"
dockan version
dockan doctor
dockan ps -a --scope all

dockan ps -a legas la aktualan deponejon. Aldonu --system por /var/lib/dockan, --user por la uzanta deponejo, aŭ --scope all por vidi ambaŭ.

Por la tuta sistemo

curl -fsSL https://raw.githubusercontent.com/Dockan-Conteneurisation-libre/Dockan/main/scripts/install.sh | sudo sh

Ĝisdatigi

dockan update
dockan update --version vX.Y.Z
dockan update --system

Aŭ el loka kopio de la fontkodo:

cd /path/to/Dockan && git pull && make install PREFIX="$HOME/.local"
Gastigaj dependaĵoj: apt, dnf, apk, pacman, zypper

Dockan instalas la pakaĵojn, kiujn ĝi bezonas, nur kiam vi eksplicite lanĉas komandon deps. Provu unue per --dry-run.

core: la bazaj iloj (ŝelo, curl, atestiloj, arkivoj, procezaj kaj retaj iloj).

dockan deps install --dry-run core
sudo env "PATH=$HOME/.local/bin:$PATH" dockan deps install core -y

full: la rekomendita kompleta agordo (ĉiuj grupoj ĉi-sube).

dockan deps install --dry-run full
sudo env "PATH=$HOME/.local/bin:$PATH" dockan deps install full -y

frankenphp por PHP-aplikaĵoj: sur Fedora, Dockan agordas la statikan PHP-deponejon kaj instalas ĝin per dnf.

sudo env "PATH=$HOME/.local/bin:$PATH" dockan deps runtime frankenphp -y
command -v frankenphp

Pakaĵgrupoj

  • tools: git, jq, arkivoj, rsync, OpenSSL, GPG, lsof kaj dosieriloj
  • frontend: Node.js kaj npm por React, Vue, Vite kaj aliaj
  • network: retaj kaj procezaj helpiloj
  • database: kutimaj klientoj de datumbazoj
  • web: Nginx kaj Caddy por lokaj inversaj prokuriloj
  • build: kompililoj kaj pkg-config
  • debug: strace, psmisc, htop kaj tcpdump
  • isolation: izolaj helpiloj, se disponeblaj
dockan deps install --dry-run frontend
sudo env "PATH=$HOME/.local/bin:$PATH" dockan deps install frontend database web build debug -y

Profiloj instalas la defaŭltajn versiojn de via distribuo. Por specifa versio, uzu la denaskan sintakson de la pakaĵadministrilo:

sudo dockan deps install --manager apt -y 'nodejs=20.*'
sudo dockan deps install --manager dnf -y nodejs-20.11.1
sudo dockan deps install --manager apk -y 'nodejs=20.11.1-r0'
sudo dockan deps install --manager zypper -y nodejs-20.11.1

Por striktaj rultempaj versioj, importu pretan lokan bazon, ekzemple dockan base runtime node:20 --from ./node20-rootfs.tar.gz. Se sudo dockan ne trovas la komandon post uzanta instalo, uzu la formon sudo env "PATH=$HOME/.local/bin:$PATH" aŭ la absolutan vojon.

Ekzemplo: WordPress kun MariaDB

PHP-aplikaĵo kun datumbazo montras la tutan laborfluon: bildoj, compose, retaj kaŝnomoj, volumoj, sankontroloj kaj sekurkopio.

name: wordpress
services:
  web:
    image: wordpress:local
    ports:
      - 8080:8080
    env:
      - DB_HOST=db
      - DB_NAME=wordpress
      - DB_USER=wordpress
      - DB_PASSWORD=change-me
    volumes:
      - wp-data:/var/www/html
    network: wpnet
    aliases:
      - web
    depends_on:
      - db
    restart: always
    healthcheck: CMD-SHELL curl -f http://127.0.0.1:8080/
  db:
    image: mariadb:local
    env:
      - DB_NAME=wordpress
      - DB_USER=wordpress
      - DB_PASSWORD=change-me
      - DB_ROOT_PASSWORD=change-root
    volumes:
      - db-data:/var/lib/mysql
    network: wpnet
    aliases:
      - db
    restart: always
    healthcheck: CMD-SHELL test -d /var/lib/mysql
networks:
  - wpnet

Ĉi tie wordpress:local kaj mariadb:local estas bildoj preparitaj loke. Vi povas ankaŭ elŝuti bildojn el registro per dockan pull. Ŝanĝu la pasvortojn antaŭ ajna uzo.

Funkciigi

dockan compose up
dockan compose health
dockan volume backup db-data wordpress-db-backup.tar.gz
Reto

Simpla loka reto kun kaŝnomoj:

dockan network create appnet
dockan run -d --name web --network appnet --alias web.local web:latest
dockan network refresh appnet
dockan network hosts appnet
dockan network doctor

Ponto kaj NAT kun publikigitaj pordoj (bezonas sudo):

dockan network create appnet --driver bridge --subnet 10.89.0.0/24 --gateway 10.89.0.1/24 --bridge dockan0
sudo dockan network enable appnet
sudo dockan run -d --name web --network appnet -p 8080:80 web:latest
Loka registro

Elsendi kaj elŝuti bildojn tra dosierujo: sen Docker Hub, sen demono, sen nuba servo.

dockan push myapp:latest /srv/dockan-registry
dockan registry ls /srv/dockan-registry
dockan pull myapp:latest /srv/dockan-registry
Sur servilo

Kontroli la sanon de la servoj kaj savi volumon:

dockan compose health -f /srv/myapp/dockan.yml
dockan volume backup data /srv/backups/data.tar.gz

Dockan Panel, por tiuj, kiuj preferas retumilon

Nedeviga interfaco por ujoj, bildoj, volumoj, stakoj, sekurkopioj kaj vivaj terminaloj.

Dockan Panel ruliĝas per la gastiga binaraĵo frankenphp. Malfermu http://127.0.0.1:9090, poste kreu la unuan administran konton: ne ekzistas defaŭlta pasvorto nek ĵetono.

command -v frankenphp || sudo env "PATH=$HOME/.local/bin:$PATH" dockan deps runtime frankenphp -y
cd /path/to/Dockan-Panel
dockan compose up

Malfermi la deponejon de Dockan Panel

La panelo konservas uzantojn, pasvortajn haketaĵojn, sekretojn 2FA/TOTP, publikajn ŝlosilojn de passkeys, stakojn kaj sekurkopiojn en la volumo dockan-panel-data. Forigi tiun volumon forigas ĉiujn tiujn datumojn.

/app/storage/auth-users.json
~/.local/share/dockan/volumes/dockan-panel-data

Por publika aliro, metu inversan prokurilon HTTPS antaŭ la panelo, kaj neniam elmetu la pordon 9090 per simpla HTTP. Passkeys funkcias nur sur localhost, 127.0.0.1 aŭ per HTTPS.

Instali la panelon por produktado

Por produktado, instalu la panelon el sistema vojo kiel /srv/dockan-panel. Tio evitas la blokadojn de SELinux sur hejmaj dosierujoj kaj startigas la panelon per systemd, por ke la paĝo Packages povu instali dependaĵojn kaj ĝisdatigi rultempojn.

sudo install -m 0755 "$HOME/.local/bin/dockan" /usr/local/bin/dockan
sudo mkdir -p /srv/dockan-panel /var/lib/dockan
sudo cp -a /path/to/Dockan-Panel/index.php /path/to/Dockan-Panel/README.md /path/to/Dockan-Panel/dockan-logo.svg /path/to/Dockan-Panel/Caddyfile /path/to/Dockan-Panel/Dockanfile /path/to/Dockan-Panel/dockan.yml /path/to/Dockan-Panel/restore-prod-storage.sh /srv/dockan-panel/
sudo restorecon -RFv /srv/dockan-panel /var/lib/dockan /usr/local/bin/dockan 2>/dev/null || true
cd /srv/dockan-panel
sudo env DOCKAN_HOME=/var/lib/dockan /usr/local/bin/dockan compose autostart -f dockan.yml --name dockan-panel

Se la panelo jam havas uzantojn aŭ stakojn en loka storage/, migru ilin al la produkta volumo. La skripto konservas datitan sekurkopion de la ekzistanta volumo en /var/lib/dockan/volumes/, kopias la datumojn, riparas la etikedojn de SELinux kaj restartigas la servon.

cd /path/to/Dockan-Panel
sudo ./restore-prod-storage.sh
