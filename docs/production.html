Ĝisdatigi aplikaĵon

Validu Dockan sur la ĝusta distribuo, kerno, izolada reĝimo, reto kaj aplikaĵo, kiujn vi uzos. Uzu nemoveblajn versiojn: evitu deploji ĉion kiel latest.

dockan build -t myapp:v1.2.0 .
dockan tag myapp:v1.2.0 myapp:stable
dockan compose redeploy -f /srv/myapp/dockan.yml

dockan compose redeploy haltigas la projekton, forigas la malnovajn ujojn, rekonstruas la servojn kun build: kaj restartigas la projekton. Por servo de systemd:

sudo systemctl restart dockan-myapp.service

Malfari ĝisdatigon

Konservu la antaŭan etikedon antaŭ ĉiu ĝisdatigo:

dockan tag myapp:stable myapp:previous
dockan build -t myapp:v1.3.0 .
dockan tag myapp:v1.3.0 myapp:stable
dockan compose redeploy -f /srv/myapp/dockan.yml

Se la ĝisdatigo malsukcesas, remetu la antaŭan version:

dockan tag myapp:previous myapp:stable
dockan compose redeploy -f /srv/myapp/dockan.yml

Tenu la datumojn en volumoj, por ke malfaro ne forigu ilin, kaj savu gravajn volumojn antaŭ riska ĝisdatigo:

dockan volume backup data /srv/backups/myapp-data-v1.2.0.tar.gz
dockan volume restore data-restored /srv/backups/myapp-data-v1.2.0.tar.gz

Restarigo ĉiam okazas en novan, malplenan volumon.

Sankontroloj

Metu la sankontrolojn en Dockanfile aŭ dockan.yml:

services:
  web:
    image: myapp:stable
    healthcheck: CMD-SHELL curl -f http://127.0.0.1:8080/

Kontroli unu ujon, poste ĉiujn servojn de projekto:

dockan health myapp-web
dockan compose health -f /srv/myapp/dockan.yml

Aplikaĵo kun datumbazo

Por aplikaĵo kun datumbazo, uzu en compose:

  • depends_on, por starti la datumbazon antaŭ la aplikaĵo
  • aliases, por ke la aplikaĵo trovu la datumbazon per la nomo db
  • env kun normaj nomoj kiel DB_NAME, DB_USER kaj DB_PASSWORD
  • volumojn por la stato de la datumbazo kaj sankontrolojn por ambaŭ
name: myapp
services:
  web:
    image: myapp:stable
    depends_on:
      - db
    env:
      - DB_HOST=db
      - DB_NAME=myapp
      - DB_USER=myapp
      - DB_PASSWORD=change-me
    network: appnet
    aliases:
      - web
    healthcheck: CMD-SHELL curl -f http://127.0.0.1:8080/
  db:
    image: db:stable
    volumes:
      - db-data:/var/lib/db
    env:
      - DB_NAME=myapp
      - DB_USER=myapp
      - DB_PASSWORD=change-me
    network: appnet
    aliases:
      - db
    healthcheck: CMD-SHELL test -d /var/lib/db
networks:
  - appnet

Komencaj skriptoj de datumbazo ankoraŭ ne estas universalaj: metu ilin en la bildon de la datumbazo, en skripton hooks/prestart aŭ en propran komandon. Ŝanĝu la pasvortojn antaŭ ajna uzo.

Ŝarĝo kun pluraj ujoj

Antaŭ ol fidi servilon, provu pli ol unu ujon kaj aktivigu la starton kun la maŝino:

dockan compose up -f /srv/myapp/dockan.yml
dockan ps -a --scope all
dockan logs myapp-web
sudo dockan compose autostart -f /srv/myapp/dockan.yml --name myapp

Por HTTP-aplikaĵoj, lanĉu ŝarĝilon el alia ŝelo aŭ alia maŝino:

wrk -t4 -c64 -d60s http://127.0.0.1:8080/
ab -n 5000 -c 50 http://127.0.0.1:8080/

Kontrolu la uzon de CPU kaj RAM, dockan compose health, la protokolojn sub ŝarĝo, la restartojn, la pordojn, la skribojn en volumojn kaj la purigon post dockan compose down.

Sekureco kaj izolado

Lanĉu dockan doctor kaj kontrolu la elektitan izoladan reĝimon:

ReĝimoRimarkoj
bubblewrapRekomendita: propraj nomspacoj PID, IPC kaj UTS, neniu Linuksa kapablo, sen root.
firejailIlo setuid; OCI-bildoj uzas bubblewrap anstataŭe.
systemd-nspawnPli forta, bezonas root kaj taŭgan rootfs.
chrootBaza izolado de dosieroj, bezonas root.
noneNur por provoj, neniam por nefidindaj aplikaĵoj.

La reĝimo auto neniam falas al none: sen izolilo, dockan run haltas kun eraro. Ruli sen izolado ĉiam postulas eksplicitan --isolation=none.

Elŝutitaj bildoj

La manifesto, la agordo kaj ĉiu tavolo devas kongrui kun siaj haketaĵo kaj grandeco. Etikedo ne estas fiksa: fiksu bildon per ĝia haketaĵo (dockan pull alpine@sha256:...) por ricevi ĝuste tiun enhavon. Malpakado restas ene de la bildo, kaj malpakita tavolo ne povas superi 64 GiB.

Publika registro povas konduki Dockan nur al publikaj HTTPS-adresoj: ĝi ne povas atingi vian lokan reton. Privata registro atingata per nomo devas esti listigita:

export DOCKAN_PRIVATE_REGISTRIES=registry.lan,nas.home:5000

Bildoj kun tavoloj zstd bezonas la ilon zstd (dnf install zstd, apt install zstd).

Haltigi ujojn

Kun systemd, ĉiu fona ujo ruliĝas en sia propra scope (cgroup), kun --memory kaj --cpus aplikitaj al ĝi: dockan stop trovas ĉiun procezon de la ujo. Ordinara uzanto bezonas la opcion linger, alie la ujoj haltus ĉe elsaluto:

sudo loginctl enable-linger "$USER"

Sen scope, Dockan trovas la procezojn per ilia grupo, ilia deveno, ilia PID-nomspaco kaj la variablo DOCKAN_RUN_ID. Ĝi ankaŭ registras la startan horon de ĉiu ujo, por neniam signali alian procezon, kiu reuzis ĝian numeron.

Sur kernoj pli malnovaj ol 6.2, aŭ kiam dev.tty.legacy_tiocsti valoras 1, dockan run en malfono restas konektita al via terminalo: rulu nefidindajn bildojn per -d.

Por produktado, preferu:

dockan run --isolation=bubblewrap myapp:stable
sudo dockan run --isolation=systemd-nspawn myapp:stable

Ponto kaj NAT

Ponto kaj NAT bezonas root kaj la retajn ilojn de la gastiganto. La nomoj de la pakaĵoj varias laŭ distribuo; kontrolu per dockan doctor.

sudo dockan deps install -y iproute2 iptables
dockan network create prodnet --driver bridge --subnet 10.89.0.0/24 --gateway 10.89.0.1/24 --bridge dockan0
sudo dockan network enable prodnet
sudo dockan run -d --name web --network prodnet -p 8080:80 myapp:stable
curl http://127.0.0.1:8080/
dockan network hosts prodnet
sudo dockan network disable prodnet

Kontrollisto antaŭ produktado

  • dockan doctor taŭgas por la celata izolado kaj reto
  • la aplikaĵo startas post restarto
  • dockan compose redeploy ĝisdatigas la aplikaĵon, kaj malfaro al la antaŭa etikedo funkcias
  • savkopioj kaj restarigo de volumoj funkcias, kaj volumoj konservas la datumojn post redeplojo
  • dockan compose health sukcesas, kaj la protokoloj estas legeblaj
  • dockan push kaj dockan pull funkcias kun la elektita loka registro
  • pluraj servoj ruliĝas kune, publikigitaj pordoj atingeblas, kaj la ŝarĝotesto sukcesas

Loka akcepta testo, kun nedeviga kontrolo de ponto kaj NAT:

make build
scripts/server-acceptance.sh
sudo DOCKAN_ACCEPT_BRIDGE=1 DOCKAN_BIN="$PWD/dockan" scripts/server-acceptance.sh

Uzu Dockan por lokaj Linuksaj deplojoj, internaj servoj, laboratorioj, memgastigado kaj kontrolataj servilaj laboroj. Por kritikaj servoj, validu la ĝustan servilan medion antaŭ ol fidi ĝin.
